# REHEARSAL Named Actor Identity Amendment

## Purpose

Refine the approved REHEARSAL design so recurring PLG characters are not represented only by anonymous task packets. The system should create a small cast of named synthetic actor identities, then cast those actors into PLG roles.

This amendment does not change canon authority. It changes how the exploratory REHEARSAL layer instantiates character performance.

## Core rule

> The actor is not the character. Mana casts an actor into the character role.

A named actor identity may have its own selected visual reference, temperament, performance strengths, and accumulated rehearsal history. None of those become PLG canon simply because the actor is playing a canon character.

## Casting sequence

For a recurring character:

1. Read locked canon facts, current Character Bible evidence, relationship context, bodily state, and the user's durable casting nudges.
2. Generate one or more candidate actor identities where useful.
3. Give each candidate a distinct actor name and derived visual identity.
4. Evaluate candidates for ensemble distinctness, role fit, thumbnail readability, and canon compatibility.
5. Mana chooses the actor.
6. Mana formally casts that actor into the PLG character role.
7. The selected actor receives scene-local packets and begins accumulating rehearsal evidence while playing that role.

Example conceptual form:

`named actor identity -> cast as Greg -> scene-local Greg packet -> rehearsal take -> evidence/discoveries`

Do not use the PLG character name as the actor's own identity name.

## Mana's role

Mana is the casting director and identity steward.

Mana may:

- name candidate actors
- choose among casting candidates
- reject a visually or behaviorally generic actor
- recast a role later when evidence shows the current casting is weak
- preserve a compact reason for a consequential casting choice

Mana should not micromanage every visual or behavioral trait. Candidate actors are allowed to contribute interpretation where canon is silent.

## Sticky user nudges

The user's few explicit visual or identity nudges are durable casting constraints and should survive future compiles unless the user changes them or canon contradicts them.

Current examples include:

- Greg: scruff/beardish, not pretty-boy polished, disheveled intensity, slightly feral/theatrical energy, intense without needing the prose to explain that intensity; early-book left BKA with two crutches and no later peg/prosthetic leakage
- Lyssa: tall, thin/lithe Black woman with Afro-textured or afro-ish hair
- Antonius: Black
- Alden: islander boy and visually unmistakable from Greg
- ensemble-wide: recurring characters must remain distinguishable at low resolution, not merely when zoomed in

These nudges should be stored as user-authored anchors with higher persistence than ordinary generated casting interpretation.

## Actor identity packet

A named actor identity may contain:

- actor name
- selected visual reference
- casting role
- role start/version
- sticky user nudges inherited from the character
- locked canon facts relevant to embodiment
- derived physical interpretation
- promoted behavioral tendencies for the role
- relationship-specific evidence
- current scene objective and pressure
- anti-caricature warnings
- rehearsal strengths discovered over time
- known failure modes or overacting tendencies
- provenance/freshness metadata

The actor's permanent identity should remain compact. Scene state is compiled on demand.

## Identity learning

Actors may help discover how a character feels in motion, but synthetic performance does not self-authorize canon.

Useful discoveries can become:

- rehearsal hypotheses
- promoted derived tendencies when independently supported by current canon or accepted prose returns
- visual identity refinements
- relationship-behavior notes
- blocking or object-handling tendencies

Synthetic repetition does not count as independent evidence.

## Recasting

Recasting is allowed.

A recast should happen when:

- the actor repeatedly collapses into another character's voice or silhouette
- the selected visual identity conflicts with current canon or era
- the actor consistently overplays a trait into caricature
- later canon evidence materially changes the role model
- Mana judges another candidate to produce materially stronger distinction or performance

Historical rehearsal evidence remains attributable to the actor/version that produced it.

## Cost discipline

Do not create a large autonomous cast for every one-off speaker.

Use named persistent actors primarily for recurring or structurally important characters. Minor characters can continue to use lightweight anonymous scene-local packets unless they become recurring enough to justify casting.

## Pilot

The first pilot should cast a small core ensemble before full rehearsal:

- Greg
- Antonius
- Hessa
- Lyssa
- Alden
- Arlo
- at least three theatre recurring characters for an ensemble collision test

For each selected actor, persist:

- actor name
- PLG role
- selected visual reference or reference status
- sticky user anchors
- brief casting rationale
- role version

Then run rehearsals with those actors and evaluate whether named identity produces stronger voice, movement, blocking, and relationship behavior than anonymous packets alone.

## Success criterion

The named-actor approach is successful if the cast becomes easier to distinguish behaviorally and visually while preserving canon truth and without turning recurring characters into rigid gimmicks.
