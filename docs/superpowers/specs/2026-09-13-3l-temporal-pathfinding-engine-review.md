## Scope check

The first implementation should remain markdown-first and lightweight. It does not need a database, workflow service, persistent agent hierarchy, or automated publication system.

The first runnable slice is only:

1. prose lock authority
2. shared seed
3. provisional 300-map import
4. four window work orders
5. seam templates
6. connected rehearsal template
7. Story Sync promotion template

Actual speculative window generation is the first engine run, not part of the infrastructure build itself.

## Anti-railroad check

The design does not require exactly 300 final Records. It uses 300 as a broad search horizon.

The design explicitly allows Records to be deleted, moved, merged, split, retitled, or replaced during rehearsal.

The known ending constrains late-story obligations without dictating exact earlier events.

The temporal engine may know future possibilities, but that knowledge may not leak into young Greg's lived perception.

## Recovered design fidelity

The design preserves the strongest mechanics from the earlier distributed temporal prose experiment:

- common compact seed
- simultaneous A/B/C/D independence
- confidence gradient
- overlapping temporal seams
- no early locking
- preserved first-pass evidence
- explicit convergence/fork classification
- connected rehearsal before promotion

The primary deliberate adaptation is cost: the first 3L run produces title-plus-one-sentence trajectory candidates rather than full speculative prose across the entire horizon.
