# CHAT ROUTER

Use this at the start of any Peg-Leg Greg chat, Codex task, or work session that can access the repository.

## Base instruction

You are working on Peg-Leg Greg through the shared GitHub repository.

Before substantial work:

1. Read `project_brain/README.md`.
2. Read `project_brain/production/WORKFLOW.md`.
3. Identify the current lane and read only the relevant project-brain files.
4. Check current repository/manuscript authority before making canon-dependent claims or changes.

Treat GitHub project-brain files as durable shared memory, not infallible canon. The current manuscript outranks summaries. Explicit canon outranks exploratory possibilities. Newer authority outranks stale handoffs.

When work produces durable changes, update the relevant project-brain file compactly. Do not paste chat transcripts. Do not save hidden reasoning. Record facts, decisions, tensions, unresolved questions, and next executable edges.

When exploring, clearly distinguish CANON / STRONG INFERENCE / POSSIBILITY / QUESTION.

When writing manuscript, do not let project-brain summaries override what the current manuscript actually establishes.

When editing UI, visuals, tooling, or publishing infrastructure, keep those changes separable from active manuscript changes whenever practical.

## Lane shortcuts

### Manuscript
Read: canon + story + relevant characters/world.
Write chapters first. Update durable state afterward.

### Writers' Room / Story Control
Read: current manuscript + story + relevant canon/characters/world.
Explore freely, but only durable residue goes back to GitHub.

### Worldbuilding
Read: current manuscript evidence + world + systems + affected characters/story.
Build where story pressure creates a need. Avoid encyclopedia completion for its own sake.

### Character work
Read: current manuscript evidence + character file + relevant story/canon.
Track change over time, relationships, voice, pressures, capabilities, and continuity risks.

### Prose edit
Read the actual current prose. Improve prose without silently changing plot/canon/outcomes.

### Visual / UI
Read reader visual state + relevant manuscript scenes. Do not overwrite manuscript files as part of presentation work.

### Publishing
Validate first. Prefer small, legible commits. Never restore stale whole-file versions over newer authority.
