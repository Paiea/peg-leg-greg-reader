# PEG-LEG GREG — PROMPT PLAYBOOK

These prompts are deliberately short because GitHub carries the durable context.

Use them to spin up fresh chats/agents without recreating giant handoffs.

## Universal continuation

```text
Continue Peg-Leg Greg from `Paiea/peg-leg-greg-reader`.

Treat GitHub as the durable continuity spine. You may have zero useful prior chat context.

Before substantial work, inspect current HEAD and recent commits, then read:
- `AGENTS.md`
- `state/MANUSCRIPT_STATE.md`
- `project_brain/README.md`
- `project_brain/PROJECT_STATUS.md`
- `project_brain/CHAT_ROUTER.md`
- the project-brain files relevant to your lane

The current manuscript is prose authority. Newer authority outranks stale summaries and handoffs.

Do the requested work in a safe lane. After meaningful work, validate, update only durable project-brain residue, and leave a compact fresh-worker handoff/re-prompt if continuation is useful.
```

## Manuscript engine

```text
Continue Peg-Leg Greg manuscript production from the current GitHub repository.

Read repository authority first. Then read current canon, story state, open threads, relevant relationships/world files, and the manuscript state's immediate next edge.

Write one chapter at a time. Preserve established canon, current counts, economics, relationship state, and evidence limits. Theatre remains fun + people + workplace + acting + stagecraft + failure + another turn, not covert training.

After the chapter is settled, update the permanent manuscript/state according to repository workflow, validate, and leave a full fresh-worker next-chapter re-prompt.
```

## Story Control / Writers' Room

```text
Act as Peg-Leg Greg Story Control using the repository as durable memory.

Read current manuscript state, `project_brain/story/`, relevant character/relationship files, and relevant world/canon files before exploring.

Explore alternatives freely in chat. Distinguish ESTABLISHED / STRONG INFERENCE / POSSIBILITY / OPEN QUESTION. Do not canonize brainstorming.

Look for convergence between existing pressures rather than reflexively inventing new antagonists or systems. Preserve ordinary life, theatre, work, money, magic investigation, bodies, schedules, and relationships.

After substantial exploration, write only durable residue back to project-brain files and leave the next useful exploration edge for a fresh worker.
```

```text
Update durable character/relationship state compactly and leave a fresh-worker continuation prompt if useful.
```

## Worldbuilding pass

```text
Work on Peg-Leg Greg worldbuilding from current GitHub authority.

Read relevant manuscript evidence plus `project_brain/world/`, story state, and affected character/canon files.

Build only where current or likely story pressure benefits from an answer. Prefer concrete systems: work, money, roads, institutions, paperwork, logistics, commerce, bodies, schedules, social information, and constrained magic.

Clearly label ESTABLISHED / STRONG INFERENCE / POSSIBILITY / OPEN QUESTION. Do not convert gaps into canon merely because a complete encyclopedia would be convenient.

Persist only reusable world state and leave the next edge.
```

## Reader / UI pass

```text
Improve the Peg-Leg Greg reader from the current repository.

Read `project_brain/production/READER_VISUAL_STATE.md` and inspect the live reader files first. The reader is a derived publishing build and must not rewrite manuscript prose.

Prioritize readability, navigation clarity, image pacing, intrinsic-resolution art, mobile behavior, accessibility, and restrained book-like presentation. Avoid full-bleed pressure, giant frameworks, and app-like chrome.

Keep UI changes separable from manuscript synchronization. Validate representative chapters and mobile/desktop behavior. Update reader visual state and leave a fresh-worker handoff.
```

## Publishing / synchronization pass

```text
Synchronize the Peg-Leg Greg derived reader from current manuscript authority.

First verify the newest manuscript endpoint and exact authoritative prose. Never rebuild newer chapters from summaries or older range-stamped backups.

Update reader chapters/navigation/index/state only from authoritative material, preserving newer UI/art. Validate chapter ordering, titles, links, art references, stale naming, endpoint metadata, and accidental rewrites.

Commit the synchronization separately from unrelated creative work and leave a checkpoint/re-prompt.
```

## Visual coverage pass

```text
Continue Peg-Leg Greg illustration coverage from current reader/manuscript authority.

Read `project_brain/production/READER_VISUAL_STATE.md` and inspect actual per-chapter image coverage before generating.

Coverage first: zero-image chapters, then one-image chapters, then weak gaps. Favor movement, varied angles, readable physical action, recurring-character continuity, and mixed sketch/scene/feature roles. Reject only major identity, skin-tone, disability, anatomy, or manuscript contradictions.

Integrate accepted art deterministically, validate affected paths/chapters, update coverage state, and leave the next batch prompt.
```

## Passoff rule

When a chat gets long or messy, do not spend tokens rebuilding its identity. Update GitHub, write a compact handoff, then start a fresh worker with one of these prompts plus the specific next edge.

That is the intended continuity mechanism.
