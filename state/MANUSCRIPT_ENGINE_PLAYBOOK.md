# PEG-LEG GREG — MANUSCRIPT ENGINE PLAYBOOK

This file preserves the durable working method of 01 / Manuscript Engine so a fresh chat, Codex session, or future model can reproduce the useful behavior without depending on lost conversation context.

It is NOT a canon summary and should not become one. Current facts belong in `MANUSCRIPT_STATE.md` and `OPEN_THREADS.md`. Exact story belongs in the manuscript.

## 1. Start from GitHub, not memory

Before forward writing, read at minimum:

1. `state/PROJECT_STATE.md`
2. `state/MANUSCRIPT_ENGINE_PLAYBOOK.md`
3. `state/MANUSCRIPT_WORKFLOW.md`
4. `state/MANUSCRIPT_STATE.md`
5. `state/OPEN_THREADS.md`
6. `state/MANUSCRIPT_CHAPTER_INDEX.md`
7. the current edge of `state/manuscript/Peg_Leg_Greg_Running_Manuscript.md`

Read additional engine state only when relevant. Some older state files may have stale endpoints. Never let a stale summary overrule newer manuscript prose.

## 2. Authority discipline

Use this order for story decisions:

1. newest authoritative manuscript prose;
2. explicit current author decisions;
3. established durable story-control decisions that do not conflict with newer prose;
4. current manuscript state/open threads;
5. developmental exploration.

If sources conflict, preserve the newer authoritative material and record the conflict rather than silently blending incompatible versions.

Do not reconstruct missing exact prose from summaries. A summary can preserve continuity, not wording.

## 3. One chapter means one chapter

Default production unit is ONE complete new chapter.

Do not respond to a chapter-writing prompt with only an outline, scene list, planning essay, or questions when the supplied direction is sufficient to write.

The usual target is 2,500–4,000 words and clear of 2,500 unless the author changes it.

The chapter should function as story, not as a container for every active thread.

## 4. Story-engine rotation

Peg-Leg Greg works best when live engines alternate and braid instead of all advancing every chapter.

Common engines include:

- ordinary household / Lyssa / food / money / errands;
- theatre workplace / rehearsal / performance / backstage labor;
- Hessa / controlled magic evidence;
- Vale / debt / suitable labor / commercial pressure;
- friendships and city life;
- threat / Bren / commercial interference;
- physical adaptation and ordinary body costs;
- longer exploratory threads.

After one engine receives several chapters of pressure, seriously consider letting it breathe while another moves.

Do not reward every clue immediately with investigation.
Do not answer every question in the next chapter.
Do not create escalation merely because escalation is available.

Ordinary life is not filler. It is part of the book's engine.

## 5. Greg's intelligence

Greg is intelligent, observant, analytical, practical, and often useful.

He is NOT a generic mastermind.

His strongest pattern is:

OBSERVE → FORM A NARROW IDEA → TEST / ACT → ENCOUNTER ANOTHER PERSON OR REALITY → REVISE.

Allow him to:

- misunderstand;
- overreach mentally;
- ask the wrong question;
- notice something without knowing its meaning;
- rationalize;
- be corrected by people with deeper expertise;
- make ordinary mistakes;
- perform competently without brilliance;
- decide not to pursue a tempting clue.

Do not make every Greg observation correct in retrospect.

His older-life memory is associative and incomplete, not a searchable database.

## 6. Greg's voice and prose

Preserve:

- dry humor;
- practical irritation;
- physical awareness;
- odd associations;
- uncertainty and self-correction;
- analytical attention without constant thematic explanation;
- nineteen-year-old embodiment interacting with older remembered experience.

Favor fuller natural paragraphs with intentional short beats rather than endless mechanical fragments.

Keep dialogue attribution clear. `said` is useful.

Keep bodies, objects, routes, rooms, weather, food, clothing, tools, benches, doors, streets, crutches, fatigue, and work physically present.

Do not explain a scene's meaning again after the scene has already made it clear.

NO EM DASHES in manuscript prose.

## 7. Theatre must remain theatre

Visible theatre trajectory:

FUN → PEOPLE → WORKPLACE → ACTING → STAGECRAFT → FAILURE → ANOTHER TURN.

Long-range direction:

THEATRE → PERFORMANCE → MISDIRECTION → ILLUSION → MASKS → CONTROL OF PERCEPTION → eventual dangerous bluff.

The long-range direction is directional only. It is not a checklist and must not turn current theatre chapters into obvious future-bluff training.

Greg should:

- work;
- rehearse;
- perform;
- screw up;
- solve mundane problems;
- enjoy people;
- deal with backstage nonsense;
- participate in real plays;
- encounter audiences;
- gradually become more comfortable performing.

Experienced theatre workers remain substantially better than Greg at theatre craft.

Let the strongest performance beat belong to someone else often.

A Greg mistake does not need a brilliant improvised rescue. Sometimes another actor bridges. Sometimes the scene simply survives.

## 8. Hessa and magic evidence

Hessa owns mana safety, experimental discipline, supervision, repeatability, apparatus continuity, and evidentiary language.

She is NOT Greg's theatrical illusion teacher.

Magic scenes should change as few variables as practical and ask one narrow question at a time.

Track exact counts when attempts occur.

Distinguish:

- observed once;
- repeated;
- provisionally supported;
- reliable;
- established;
- generalized.

Never promote one category into another because the result is exciting.

Greg's body is part of the apparatus. Hand, wrist, forearm, shoulder, residual limb, phantom state, posture, fatigue, and ordinary physical load can affect interpretation.

Hessa stops when safety or data quality says stop. Greg does not earn reckless extra attempts through determination.

Do not turn tiny controlled external effects into generalized telekinesis, combat utility, theatrical magic, arbitrary object control, or established range without evidence.

Keep magic and theatre domains separate until the manuscript genuinely earns a bridge.

## 9. Threat / evidence discipline

Threat should progress through concrete pressure, costs, questions, behavior, and imperfect information rather than omniscient villain exposition.

Record what witnesses actually saw or heard.

Preserve distinctions such as:

- description match versus identity;
- direction of travel versus destination;
- interest in money versus plan to steal it;
- association versus employment;
- warning versus threat;
- inference versus fact.

Secondary characters can be better than Greg at narrowing evidence.

Do not create a boss, gang, organization, surname, conspiracy, motive, or connection merely because one would make the pattern cleaner.

Threat does not need violence to remain consequential.

When mundane defenses work, let them work.

## 10. Lyssa and secondary-character independence

Lyssa is an independent person with work, errands, moods, obligations, preferences, fatigue, humor, and decisions.

She is not Greg's analyst, research partner, financial manager, therapist, or exposition machine.

Her observations can be sharp while remaining narrow and human.

The same principle applies broadly: Hessa, Rinna, Pessa, Antonius, theatre workers, merchants, friends, and other recurring characters have expertise and projects that do not belong to Greg.

Do not make secondary characters exist only to praise, correct, rescue, or explain Greg.

## 11. Money and debt

Currency is copper / silver / gold. Do not invent a conversion rate unless authoritative prose establishes one.

Do not invent exact purse balances.

Debt remains materially real without turning every purchase into a morality scene.

Food, soap, clothing, lodging, crutch maintenance, leisure, theatre life, and other necessary or ordinary spending can coexist with repayment.

Antonius is commercial, not automatically benevolent or villainous.

Do not create a Vale connection to unrelated threat threads without evidence.

## 12. Disability / body

Greg has a permanent LEFT below-knee amputation with knee preserved, right leg intact, and uses two crutches in the current continuity.

Keep disability materially present without turning every scene into rehabilitation, inspiration, tragedy, or super-adaptation.

Use activity-specific costs and geometry:

- route width;
- chair placement;
- hands occupied by crutches;
- shoulder/hand load;
- residual-limb comfort;
- right-leg load;
- stairs;
- carrying;
- standing duration;
- wet or uneven streets.

Other people may make practical adjustments without delivering lessons about disability.

## 13. Chapter titles

Titles usually identify a role, function, position, or identity Greg actually occupies in the chapter.

Before finalizing, check `MANUSCRIPT_CHAPTER_INDEX.md` for repeats.

Repeats exist historically, so this is a preference rather than a reason to distort a chapter. Prefer a fresh accurate title over a forced novelty.

## 14. Drafting behavior

Before drafting, identify privately:

- the chapter's primary function;
- which engine moves;
- which engines deliberately do not move;
- the chapter's ordinary-life anchor;
- one or two likely mistakes/limitations;
- the evidence ceiling for any mystery or magic result;
- the physical route through the day.

Then write the chapter rather than continuing to plan it.

Do not mechanically satisfy every optional beat from a prompt. The prompt is steering, not a checklist. If the prose produces a better canon-consistent path, follow it and update state from what actually happened.

## 15. Light prose / continuity pass

After drafting:

- remove accidental repetition;
- repair unclear attribution/pronouns;
- improve paragraph rhythm;
- tighten weak transitions;
- remove production/meta language;
- check names and physical continuity;
- check money/magic/threat claims against established evidence;
- preserve intentional humor and bluntness;
- do not polish away Greg's voice;
- do not change story outcomes during a light pass.

For a requested heavy prose pass, sentence and paragraph restructuring may be much stronger, but canon, characterization, scene intent, and outcomes remain protected unless repairing an obvious contradiction.

## 16. Verification before shipping

Do not claim a chapter is shipped until fresh checks support the claim.

At minimum verify:

- chapter exists in the intended permanent manuscript path;
- word count meets the requested target;
- manuscript chapter contains zero em dash characters;
- title/index endpoint agree;
- manuscript state endpoint agrees;
- magic counts and other numerical continuity agree with what actually happened;
- no stale file was used to overwrite newer GitHub authority.

If verification fails, report the actual state and repair before claiming completion.

## 17. GitHub write strategy

For normal one-chapter forward production, small direct updates to `main` are acceptable when the author has explicitly asked to continue and ship.

For broad or risky work, prefer a GitHub branch before changing authority. Examples:

- mass prose editing;
- large reader rebuilds;
- illustration replacement batches;
- manuscript consolidation / historical synchronization;
- broad renames;
- structural repository cleanup.

The goal is to avoid meaningful finished work existing only inside chat or an untracked local file.

CHAT = exploration / temporary working context.
GITHUB BRANCH = durable work in progress.
GITHUB MAIN = current accepted authority.

## 18. State hygiene

Do not make a new state file every chapter.

Update living files in place.

`MANUSCRIPT_STATE.md` answers: WHERE ARE WE NOW?

`OPEN_THREADS.md` answers: WHAT IS STILL LIVE / UNRESOLVED?

`MANUSCRIPT_WORKFLOW.md` answers: WHAT FILES / STEPS DO WE USE?

`MANUSCRIPT_ENGINE_PLAYBOOK.md` answers: HOW SHOULD 01 THINK AND WORK?

Do not duplicate large canon summaries across all four files.

Historical files can remain until deliberate cleanup, but they should not become active forward targets.

## 19. Re-prompt ritual

After a completed chapter and GitHub update, chat should contain:

1. a compact production note;
2. the actual chapter title;
3. verified word count and em-dash status;
4. a brief note about what moved;
5. one FULL copyable next-chapter re-prompt in a single code block.

The next re-prompt must be generated from what ACTUALLY happened in the new chapter, not merely copied from what the previous prompt predicted.

GitHub is durable memory.
The re-prompt is the steering wheel.

## 20. Failure mode

If exact source prose is unavailable, do not fake it.

If GitHub cannot be written, do not claim it was updated.

If a chapter cannot be verified, preserve the draft and report the gap.

If a state file is stale, update or quarantine its stale claim rather than letting it silently control newer work.

Prefer an explicit synchronization gap over invented continuity.
