# FORWARD REHEARSAL WORKFLOW

Project-local pre-prose REHEARSAL contract for Peg-Leg Greg.

This workflow begins with the Chapter 493 proving run. Exact manuscript prose remains the only story authority.

## Core loop

`CURRENT GITHUB AUTHORITY -> RECENT RHYTHM -> RELEVANT STORY MEMORY -> COMPETING POSSIBILITIES -> REHEARSAL DISCOVERIES -> OPTIONAL PERFORMANCE -> SELECTED SCENE PACKET -> PROSE -> LIGHT VALIDATION -> STORY SYNC -> NEXT GITHUB AUTHORITY`

REHEARSAL happens before prose. It returns discoveries and a preferred pressure shape, not a chapter draft.

PERFORMANCE is optional. Use it only when embodied behavior is materially uncertain or important.

## 1. Read current authority

Before every chapter:

- read current `main`;
- read `MANUSCRIPT_STATE.md` and its executable trailhead;
- read the exact latest chapter and enough neighboring prose to understand current rhythm;
- read `OPEN_THREADS.md` for genuinely live pressures;
- read `converged-memory.json` and relationship memory only when relevant;
- read specialist state only when the proposed pressure actually needs it.

Previous chat is optional context. It is never authority.

## 2. Inspect recent rhythm

Look across the last 3-6 chapters and identify:

- repeated chapter function;
- repeated Greg role;
- repeated emotional amplitude;
- repeated uncertainty type;
- repeated work/problem grammar;
- recent action pressure;
- recent fantasy density;
- which characters or systems have owned decisive action.

The next viable claim should not be rejected merely because it resembles an earlier chapter, but `new nouns / same function` is a warning.

## 3. Build a light pressure packet

Use only what the scene needs.

Record:

- `pressure`: what is forcing a decision or behavior now;
- `greg_goal`: what Greg wants in the immediate scene;
- `other_goals`: what materially affecting characters or institutions want;
- `unknowns`: what nobody is allowed to know yet;
- `hard_locks`: body, money, magic, chronology, geography, relationship, ownership, evidence ceilings;
- `residue`: what could remain after the scene if it matters.

Do not turn character packets into trait summaries. Prefer behavior under conditions.

## 4. Explore competing possibilities

Default range: 2-5 beat-level possibilities.

A normal set should include some combination of:

- conservative continuation of the strongest live claim;
- higher-pressure version that changes consequence, ownership, or scene grammar;
- lateral version that lets a different character, institution, environment, or unresolved pressure own more of the chapter.

Do not draft full alternate chapters.

For each possibility, inspect:

- what materially changes;
- who owns decisive knowledge/action;
- where Greg is tempted to overclaim or over-own;
- what observable character behavior becomes possible;
- what protected uncertainty stays protected;
- what residue survives;
- what recent chapter grammar it repeats or breaks.

REHEARSAL may conclude that the obvious trailhead is already best.

## 5. Return discoveries

REHEARSAL output should be compact enough to render from.

Useful discoveries:

- preferred scene pressure;
- character behavior under conditions;
- relationship behavior;
- ownership boundaries;
- useful staging/environment/object/timing opportunities;
- silence/interruption choices;
- where another person should know more than Greg;
- where Greg may be simply correct;
- which uncertainty must remain unresolved;
- which alternatives lost and why.

Select only compatible discoveries. Do not combine every interesting beat into one maximal scene.

## 6. Decide whether PERFORMANCE earns its cost

Use PERFORMANCE when the scene's main uncertainty depends on actual embodied behavior, such as:

- relationship confrontation where distance, timing, silence, gaze, interruption, or object handling carries meaning;
- theatre or performance where playable behavior is the actual question;
- action, rescue, pursuit, physical training, danger, or environmental pressure where body/environment determine plausibility;
- disability/access geometry where movement changes outcome;
- high-pressure ensemble behavior where who moves, waits, blocks, yields, or acts first matters more than plot logic alone.

Do not invoke PERFORMANCE merely because:

- named actors are present;
- the scene contains dialogue;
- the scene is emotionally important;
- REHEARSAL already resolved the story choice;
- more heat feels impressive.

If used, PERFORMANCE must preserve hard locks and private-thought boundaries. It returns embodied evidence, not canon.

## 7. Select the scene packet

The selected packet contains:

- scene pressure;
- required result or protected non-result;
- ownership boundaries;
- surviving behavioral discoveries;
- relevant environment/objects;
- any PERFORMANCE evidence;
- explicit protected uncertainty;
- likely residue.

This is a rendering guide, not a screenplay and not mandatory beat order.

## 8. Render one chapter

Write one complete chapter through the normal Manuscript Engine.

The prose renderer can discover better sentence-level or beat-level solutions while writing. Do not force the final chapter to literalize rehearsal language.

If prose discovers a stronger canon-consistent solution than the rehearsal packet, the prose can win.

## 9. Validate

Run the normal chapter checks:

- sequential chapter number;
- `THE [ROLE]` title and title-history check;
- target length unless intentionally varied;
- no em dashes in manuscript prose;
- dialogue ownership;
- body continuity;
- money/economy continuity when relevant;
- magic evidence ceilings when relevant;
- protected uncertainty;
- no protagonist authority leakage;
- no stale state overriding newer prose.

## 10. Story Sync from actual prose

After the chapter is accepted:

- update `MANUSCRIPT_STATE.md` from what actually happened;
- update `OPEN_THREADS.md` only when a live pressure materially changes;
- update the compact recent-title window as useful;
- update the proving-run record with what rehearsal discoveries survived, changed, or died in prose;
- record any real character/environment surprise;
- record whether protagonist gravity improved or worsened;
- record whether converged memory materially helped selection;
- promote durable behavioral memory only from canon-supported evidence.

The next chapter begins from this new GitHub authority.

## Proving run discipline: 493-500

The proving ledger is:

`state/editorial/rehearsal/forward/proving-run-493-500.json`

For each chapter, complete its record before advancing.

No chapter is required to use PERFORMANCE.

No chapter is required to visibly use every active story engine.

No chapter is required to choose the hottest explored possibility.

A quiet chapter can be the correct result if its situation, social function, pressure, or residue is genuinely new.

## Evaluation at 500

Judge the workflow on:

1. scene-choice quality before drafting;
2. character-specific surprise without canon breakage;
3. protagonist-gravity reduction;
4. PERFORMANCE value relative to cost;
5. usefulness of converged memory;
6. throughput and chapter durability;
7. usefulness of rejected alternatives;
8. cleanliness of story state after sync.

If the loop adds story intelligence without unacceptable process overhead, graduate it into permanent forward production. If not, simplify it. Do not answer process friction by adding a larger router.
